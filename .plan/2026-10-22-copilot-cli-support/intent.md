# Intent

Goal: Make Copilot CLI a first-class Planzilla harness and fix demonstrated Codex orchestration gaps. Let ordinary model aliases express intent naturally in the active harness while preserving explicitly pinned models, efforts and delivery-route requirements.

In scope: Bounded official-documentation and executable capability research; Copilot harness parsing, lint, installation and reinstall cleanup; portable aliases and planner-generated route qualification; deterministic pure resolution from supplied capabilities; route-based independent review; capability-aware native dispatch and proven external CLI fallback; conditional Copilot headless provider and browser support; Codex harness mismatch, DRAFT-authoring and runner diagnostic fixes; plan-scoped execution provider/model inheritance, exact model/effort validation and native/CLI propagation; strict TDD and integration regressions.

Out of scope: Executing this plan during planning, releases, permanent host installation/auth changes, unsupported capability claims, new chats or distributed scheduling, streaming agent logs, arbitrary execution deadlines, and a general process supervisor.

Constraints: Ordinary aliases need no user-written prefixes. An opus intent selects native Opus in Claude/Copilot when supported, and a researched Sol mapping under Codex; exact model IDs and explicit efforts stay pinned unless a human authorizes change. Planners may qualify delivery routes internally, including Claude Opus execution with Copilot Opus verification on one node. Route/quota independence is distinct from model family and must survive fallback. Configured planner=opus remains a portable intent: concrete Claude quota unavailability may select the proven active-Codex Sol route, while an explicit Claude route stays pinned. Keep quota and auth errors distinct and use concrete failures/capability inputs rather than provider-wide quota discovery. Use only reachable supported native tools or external CLIs; a native-only Copilot route unavailable from Codex must become a meaningful availability/handoff choice rather than fabricated reachability. Execute this plan exclusively through Codex gpt-6.1-sol: medium for N05/N07 executors and high for all other executors, JIT planners/replanners and every independent verifier/final review. Use separate verifier invocations; do not describe them as cross-provider review. Product multi-harness/cross-route scenarios use controlled mocks, with no Claude login/quota or live Claude/Copilot model call needed. Honor the user-authorized current planner dispatch override in D8 because existing CLI headers cannot set plan-local model/provider defaults; add that missing propagation control to the implementation without invalid current header fields or edits to repo config. Keep core pure, IO in commands, runtime stdlib-only, orchestrator context one-line, and actual repo config/vendored files untouched during this plan. User has pre-authorized per-node commits and pushes during later execution; none occur during planning. Tier L follows the graph's eleven nodes; all execution/check briefs are written just in time, with only the outline needed for graph review.

Definition of done: Natural aliases resolve deterministically from explicit harness/capability inputs across Claude, Copilot and Codex; both named model collisions cannot be routed by prefix alone. A cross-route exec/verify pair preserves deliberate review independence even using the same model family. Missing tools, capability uncertainty or unsatisfiable explicit constraints yield a tested fallback or actionable human question. Copilot installation, harness dispatch, conditional provider/browser behavior and Codex corrections agree across spec, kit, code and tests; plan-local Codex-only policy reaches JIT/replan/exec/final-review and exact model/effort selection is verified across supported native and CLI routes; full Ruff and pytest verification passes.
